# Methodology & data-quality notes

_Analysis date: 2026-10-13 (UTC). All scripts in `scripts/`; run from that directory with `python3 <script>.py`._

## 1. Pipeline (reproducible order)
| Step | Script | Output |
|---|---|---|
| Prices | `fetch_prices.py` | `data/processed/prices_daily.csv` (Binance ETHBTC/BTCUSDT/ETHUSDT daily closes, 2017→) |
| Screening | `screen_universe.py` | `data/processed/screen_metrics.csv`, `data/processed/npf_series/*.csv`, raw JSON in `data/raw/{opensea,nftpricefloor}/` |
| Universe table | `build_universe_csv.py` | `universe.csv` |
| Sector base rate | `sector_index.py`, `sector_activity.py` | `sector_index.csv`, `sector_activity_monthly.csv`, charts |
| Rally anatomy & beta | `rally_analysis.py` | `rally_analysis.csv` |
| Catalyst event study | `event_study.py` | `event_study.csv` (needs `data/processed/catalysts/*.csv`) |
| Charts | `charts_finalists.py` | `reports/charts/*_history.png`, `finalists_btc_rebased.png` |
| Liquidity (activity) | `liquidity_activity.py` | `liquidity_activity.csv` |
| Liquidity (order book) | `liquidity_orderbook.py` | `liquidity_orderbook.csv` (needs free OpenSea key) |

Raw API responses are stored wrapped as `{"fetched_at_utc": ..., "data": ...}`. Raw on-chain log dumps
(`data/raw/onchain/`, >300 MB) are git-ignored and regenerated by the on-chain scripts.

## 2. Definitions
- **Floor (current)**: OpenSea API v2 `collections/{slug}/stats` `total.floor_price` fetched 2026-10-13 ~21:30 UTC.
  It is the cheapest OpenSea-visible listing — not a guaranteed executable price for size, and other venues may be
  cheaper.
- **Floor (history)**: NFTPriceFloor 3-day bars (`floorNative`). Methodology is the provider's; we treat it as a
  secondary source and cross-check peaks against CoinGecko.
- **BTC terms**: floor_ETH × ETHBTC (Binance daily close on the bar date).
- **Sector index**: equal-weight geometric mean of floor relatives across the 38 universe collections with history
  from June 2022. **Survivorship bias**: the universe was selected in 2026 from collections that still trade; dead
  collections are excluded, so the true sector loss is worse than shown.
- **Abnormal return**: collection BTC-terms change ÷ sector-index BTC-terms change over the same window − 1.
- **Rally anatomy**: trough = minimum floor in a pre-rally window, peak = maximum in the rally window; "retention" =
  mean floor 90/180 days after peak ÷ peak. Trough-to-peak multiples are best-case (perfect timing) by construction.

## 3. Known data-quality issues
1. **NFTPriceFloor smooths peaks.** 3-day sampling understates intraday highs: Pudgy ATH 25.2 ETH (NPF) vs 36.3
   (CoinGecko, 2024-12-17); Milady 6.34 vs 7.35 (CoinGecko, 2024-12-01). Use NPF for trend, not exact peaks.
2. **NPF bars before June 2022 contain glitches** (e.g., Milady 0.079 ETH in May 2022). Charts start 2022-06-01.
3. **NPF project-level stats can be stale** (e.g., MAYC stats last updated 2026-02-27); current floors therefore use
   OpenSea live stats, while NPF series are used for history only.
4. **Volume includes wash trading**, especially Q1 2023 (Blur airdrop farming). Sales counts and volumes are upper
   bounds on organic activity unless the on-chain sale classifier says otherwise.
5. **CryptoDickbutts: average sale price ≈ 0.64× floor over 90 days** — the quoted floor may not be executable,
   or NPF's series mixes CDB contracts/editions. Treat CDB floor-based valuation with caution until on-chain sales
   reconcile it.
6. **ATH dates conflict across providers** (Chromie Squiggle ATH: NPF 16.4 ETH 2023-01-11 vs CoinGecko 14.0 ETH
   2023-05-29 — CoinGecko history begins later). Neither covers the 2021 cycle reliably.
7. **Wallets ≠ people.** Holder counts overstate unique collectors (multi-wallet holders) and understate them for
   vault/custody holders.
8. **Order-book depth** is OpenSea-only (if available); Blur bids — historically the deepest bid liquidity for
   PFPs — are not observable without wallet authentication, and Blur's frontend closes 2026-11-12.

## 4. Scenario conventions
- ETH/BTC is an explicit scenario input (not forecast). BTC-terms return = M × (1 − h) × (ETHBTC_s / ETHBTC_0) − 1,
  where M = floor multiple in ETH terms and h = exit haircut (spread to executable bid + fees).
- No probabilities are assigned. Instead we report conditional outcomes and the **break-even probability** of the
  favorable scenarios needed for the position to match BTC.
